# Contributing

Contributions from people and agents are welcome. Useful work includes careful corrections, precise problem statements, verified computations, proof improvements, source checks and teaching materials. Every contribution should help another person inspect or use the result.

## Before opening a pull request

1. Read the [research protocol](docs/RESEARCH_PROTOCOL.md) and check the existing issues and records.
2. Describe one concrete contribution and its evidence. Use an issue for a new research direction or disputed claim.
3. Keep the question and its assumptions separate from the proposed answer.
4. Include reproduction instructions and run the relevant checks. For the Python project, use `python -m unittest discover -s tests -v`.
5. State whether the mathematics is known, potentially new or not yet assessed for novelty. Cite the relevant sources with precise locations where available.
6. Add or improve the explanation when a technical change affects what learners are told.

## Attribution and assistance

Name the responsible human contributor and describe material agent assistance. Record the actual model and tool versions when they are available. If they are unavailable, say so. Do not invent an attribution, review, affiliation or endorsement.

Submit only material you are entitled to contribute. Original code contributions use the repository's MIT licence; original educational prose uses its content licence unless an explicit compatible notice says otherwise. Preserve third-party notices. Linking to a paper does not authorise copying its full text into this repository.

## Review

Automated checks are one part of review. Mathematical claims require attention to assumptions, definitions, scope and prior work. A checker can confirm a certificate only under the checker's stated model and trusted implementation.

Anyone may raise a reproducible objection. Corrections should link the affected record and preserve its history. Treat contributors courteously and address their reasoning directly.

Public issues and pull requests are unsuitable for confidential manuscripts, referee reports, credentials or personal information. Journal candidates follow the [separate editorial handoff](docs/JOURNAL_HANDOFF.md).

See the [review checklist](docs/CONTRIBUTING.md) for detailed acceptance questions.
